## 第1章 性能分析方法论

### 1.1 性能优化流程

```
性能优化的正确流程：

1. 测量基准 (Baseline)
   └─> 建立可重复的测试环境
   └─> 记录当前性能指标

2. 定位瓶颈 (Profile)
   └─> CPU bound? Memory bound? I/O bound?
   └─> 热点函数识别
   └─> 系统资源分析

3. 提出假设 (Hypothesis)
   └─> 为什么慢？
   └─> 理论上能快多少？

4. 实施优化 (Optimize)
   └─> 小步迭代
   └─> 每次只改一个变量

5. 验证效果 (Validate)
   └─> 性能提升了吗？
   └─> 正确性保持了吗？

6. 重复2-5直到满意
```

```cpp
// 完整的性能指标收集
class PerformanceMetrics {
public:
    // CPU指标
    struct CPUMetrics {
        double cpu_usage;           // CPU使用率
        double ipc;                 // Instructions Per Cycle
        uint64_t cycles;            // 总周期数
        uint64_t instructions;      // 总指令数
        uint64_t branch_misses;     // 分支预测失败
        uint64_t cache_misses;      // Cache缺失
    };

    // 内存指标
    struct MemoryMetrics {
        size_t rss;                 // 常驻内存（RSS）
        size_t vss;                 // 虚拟内存（VSS）
        size_t heap_size;           // 堆大小
        uint64_t page_faults;       // 页错误
        double memory_bandwidth;    // 内存带宽利用率
    };

    // I/O指标
    struct IOMetrics {
        uint64_t read_bytes;        // 读取字节数
        uint64_t write_bytes;       // 写入字节数
        uint64_t read_ops;          // 读操作次数
        uint64_t write_ops;         // 写操作次数
        double io_wait_time;        // I/O等待时间
    };

    // 延迟指标
    struct LatencyMetrics {
        double min;                 // 最小延迟
        double max;                 // 最大延迟
        double mean;                // 平均延迟
        double p50;                 // 50分位延迟
        double p95;                 // 95分位延迟
        double p99;                 // 99分位延迟
        double p999;                // 99.9分位延迟
    };

    // 收集所有指标
    void collect() {
        collect_cpu_metrics();
        collect_memory_metrics();
        collect_io_metrics();
        collect_latency_metrics();
    }

    // 输出报告
    void print_report() {
        std::cout << "=== Performance Report ===\n";
        std::cout << "CPU Usage: " << cpu_.cpu_usage << "%\n";
        std::cout << "IPC: " << cpu_.ipc << "\n";
        std::cout << "RSS: " << memory_.rss / 1024 / 1024 << " MB\n";
        std::cout << "P99 Latency: " << latency_.p99 << " ms\n";
        // ...
    }

private:
    CPUMetrics cpu_;
    MemoryMetrics memory_;
    IOMetrics io_;
    LatencyMetrics latency_;

    void collect_cpu_metrics();
    void collect_memory_metrics();
    void collect_io_metrics();
    void collect_latency_metrics();
};
```

### 1.3 Amdahl定律与性能预测

```cpp
// Amdahl定律：评估优化的理论极限
class AmdahlCalculator {
public:
    // p: 可并行化比例 (0-1)
    // n: 处理器数量
    static double theoretical_speedup(double p, int n) {
        return 1.0 / ((1 - p) + p / n);
    }

    // 示例：热点函数占比分析
    static void analyze_hotspot_potential() {
        // 假设某函数占总执行时间的60%
        double hotspot_ratio = 0.6;

        std::cout << "Hotspot占比: " << (hotspot_ratio * 100) << "%\n\n";

        // 优化该函数的潜在收益
        std::vector<double> improvements = {1.5, 2.0, 5.0, 10.0, 100.0};

        for (double speedup : improvements) {
            double new_ratio = hotspot_ratio / speedup;
            double total_speedup = 1.0 / ((1 - hotspot_ratio) + new_ratio);

            std::cout << "优化" << speedup << "倍 -> "
                      << "总体加速" << total_speedup << "倍 ("
                      << ((total_speedup - 1) * 100) << "% faster)\n";
        }
    }
};

// 示例输出：
// Hotspot占比: 60%
//
// 优化1.5倍 -> 总体加速1.18倍 (18% faster)
// 优化2倍   -> 总体加速1.43倍 (43% faster)
// 优化5倍   -> 总体加速2.00倍 (100% faster)
// 优化10倍  -> 总体加速2.27倍 (127% faster)
// 优化100倍 -> 总体加速2.44倍 (144% faster)
//
// 结论：即使将热点优化100倍，总体也只快2.44倍
```

```bash
# 3. 重组代码提高分支可预测性
```

### 3.2 火焰图分析技巧

```
火焰图阅读指南：

1. 宽度 = 样本占比 = CPU时间占比
   - 越宽的函数消耗CPU越多
   - 关注占比>5%的函数

2. 高度 = 调用栈深度
   - 高度本身不重要
   - 但深调用栈可能影响性能

3. 颜色
   - 冷色（蓝绿）：系统库/内核
   - 暖色（红橙）：用户代码
   - 颜色深浅随机（无特殊含义）

4. 平顶 = 热点
   - 火焰图顶部平坦区域是真正的热点
   - 优化这些函数收益最大

5. 查找模式
   - "Tower"模式：调用链很深但只有一条路径
     -> 可能是递归或深层抽象
   - "Plateau"模式：顶部很平
     -> 热点函数，优先优化
   - "Valley"模式：中间凹陷
     -> 调用了外部库或系统调用

示例分析：

main [===============================================] 100%
  ├─ process_data [====================================] 70%
  │   ├─ parse_input [=============================] 65%  <- 热点！
  │   │   └─ regex_match [=========================] 60%  <- 真正的瓶颈
  │   └─ validate [===] 5%
  └─ output_result [===============] 30%

结论：regex_match是最大瓶颈，占60% CPU时间
优化方向：
1. 优化正则表达式
2. 缓存匹配结果
3. 考虑更快的解析方法
```

### 3.3 实战案例

```cpp
// 案例：优化热点函数

// 火焰图显示这个函数占50% CPU时间
std::string process_line(const std::string& line) {
    std::string result;

    // 热点1：字符串拼接（30% CPU）
    for (size_t i = 0; i < line.size(); i++) {
        result += toupper(line[i]);  // 每次都重新分配！
    }

    // 热点2：正则表达式（15% CPU）
    std::regex pattern("\\d+");
    result = std::regex_replace(result, pattern, "X");

    // 热点3：查找操作（5% CPU）
    if (result.find("ERROR") != std::string::npos) {
        result = "[ERROR] " + result;
    }

    return result;
}

// 优化后
std::string process_line_optimized(const std::string& line) {
    std::string result;
    result.reserve(line.size() + 10);  // 预分配

    // 优化1：一次性分配（30% -> 2%）
    for (char c : line) {
        result.push_back(toupper(c));
    }

    // 优化2：手动替换数字（15% -> 1%）
    for (char& c : result) {
        if (c >= '0' && c <= '9') {
            c = 'X';
        }
    }

    // 优化3：优化查找（5% -> 0.5%）
    if (result.size() >= 5 &&
        result[0] == 'E' && result[1] == 'R' &&
        result[2] == 'R' && result[3] == 'O' && result[4] == 'R') {
        result.insert(0, "[ERROR] ");
    }

    return result;
}

// 性能提升：50% CPU -> 3.5% CPU（14倍加速！）
```

### 4.3 内存带宽分析

```cpp
#include <papi.h>

// 使用PAPI测量内存带宽
class MemoryBandwidthAnalyzer {
public:
    void measure(std::function<void()> workload) {
        int events[2] = {PAPI_L3_TCM, PAPI_TOT_CYC};  // L3 miss, cycles
        long long values[2];

        PAPI_start_counters(events, 2);

        auto start = std::chrono::high_resolution_clock::now();
        workload();
        auto end = std::chrono::high_resolution_clock::now();

        PAPI_stop_counters(values, 2);

        double time_sec = std::chrono::duration<double>(end - start).count();
        double l3_misses = values[0];
        double cycles = values[1];

        // 假设L3 miss访问内存，64字节Cache line
        double bytes_from_memory = l3_misses * 64;
        double bandwidth_gbps = (bytes_from_memory / time_sec) / 1e9;

        std::cout << "L3 Misses: " << l3_misses << "\n";
        std::cout << "Memory Bandwidth: " << bandwidth_gbps << " GB/s\n";

        // 理论峰值（DDR4-3200）：25.6 GB/s per channel
        // 实际可达：~20 GB/s per channel
        std::cout << "Bandwidth Utilization: "
                  << (bandwidth_gbps / 20.0 * 100) << "%\n";
    }
};

// 使用示例
void test_memory_bandwidth() {
    const size_t SIZE = 1024 * 1024 * 1024;  // 1GB
    std::vector<int> data(SIZE / sizeof(int));

    MemoryBandwidthAnalyzer analyzer;

    // 测试顺序访问
    analyzer.measure([&]() {
        volatile long long sum = 0;
        for (size_t i = 0; i < data.size(); i++) {
            sum += data[i];
        }
    });

    // 测试随机访问
    std::vector<size_t> indices(data.size());
    std::iota(indices.begin(), indices.end(), 0);
    std::random_shuffle(indices.begin(), indices.end());

    analyzer.measure([&]() {
        volatile long long sum = 0;
        for (size_t idx : indices) {
            sum += data[idx];
        }
    });
}
```

### 5.2 微基准测试陷阱

```cpp
// 陷阱1：死代码消除
static void BM_DeadCodeElimination_Bad(benchmark::State& state) {
    for (auto _ : state) {
        int result = expensive_computation();
        // 编译器发现result未使用，优化掉整个计算！
    }
}

static void BM_DeadCodeElimination_Good(benchmark::State& state) {
    for (auto _ : state) {
        int result = expensive_computation();
        benchmark::DoNotOptimize(result);  // 防止优化
    }
}

// 陷阱2：常量折叠
static void BM_ConstantFolding_Bad(benchmark::State& state) {
    for (auto _ : state) {
        int result = factorial(10);  // 编译期计算！
        benchmark::DoNotOptimize(result);
    }
}

static void BM_ConstantFolding_Good(benchmark::State& state) {
    int n = state.range(0);
    for (auto _ : state) {
        int result = factorial(n);  // 运行时计算
        benchmark::DoNotOptimize(result);
```

### 6.1 低开销性能监控

```cpp
// 生产环境性能监控（低开销）
class ProductionMonitor {
private:
    struct Metrics {
        std::atomic<uint64_t> request_count{0};
        std::atomic<uint64_t> error_count{0};
        std::atomic<uint64_t> total_latency_us{0};

        // 使用无锁环形缓冲区记录延迟分布
        static constexpr size_t HISTOGRAM_SIZE = 100;
        std::array<std::atomic<uint64_t>, HISTOGRAM_SIZE> latency_histogram{};
    };

    Metrics metrics_;

    // 采样：只记录1%的请求详情（降低开销）
    static constexpr int SAMPLE_RATE = 100;

public:
    void record_request(uint64_t latency_us, bool success) {
        metrics_.request_count.fetch_add(1, std::memory_order_relaxed);

        if (!success) {
            metrics_.error_count.fetch_add(1, std::memory_order_relaxed);
        }

        // 采样
        if (rand() % SAMPLE_RATE == 0) {
            metrics_.total_latency_us.fetch_add(latency_us,
                                                 std::memory_order_relaxed);

            // 更新直方图
            size_t bucket = std::min(latency_us / 100,
                                     metrics_.HISTOGRAM_SIZE - 1);
            metrics_.latency_histogram[bucket].fetch_add(1,
                                                          std::memory_order_relaxed);
        }
    }

    void print_stats() {
        uint64_t requests = metrics_.request_count.load();
        uint64_t errors = metrics_.error_count.load();
        uint64_t total_latency = metrics_.total_latency_us.load();

        std::cout << "Requests: " << requests << "\n";
        std::cout << "Errors: " << errors << " ("
                  << (errors * 100.0 / requests) << "%)\n";
        std::cout << "Avg Latency: " << (total_latency / (requests / SAMPLE_RATE))
                  << " us\n";

        // 延迟分布
        std::cout << "\nLatency Distribution:\n";
        for (size_t i = 0; i < metrics_.HISTOGRAM_SIZE; i++) {
            uint64_t count = metrics_.latency_histogram[i].load();
            if (count > 0) {
                std::cout << "[" << (i * 100) << "-" << ((i+1) * 100)
                          << " us]: " << count << "\n";
            }
        }
    }
};
```

### 7.1 自动化性能测试

```cpp
// CI/CD集成的性能回归测试
class PerformanceRegressionTest {
public:
    struct Baseline {
        double mean_latency;
        double p99_latency;
        double throughput;
    };

    // 加载历史基准
    static Baseline load_baseline(const std::string& test_name) {
        // 从数据库/文件加载
        return {100.0, 200.0, 10000.0};  // 示例值
    }

    // 运行测试并比较
    static bool check_regression(const std::string& test_name,
                                  double threshold = 0.10) {  // 10%阈值
        Baseline baseline = load_baseline(test_name);

        // 运行当前测试
        auto current = run_performance_test(test_name);

        // 检查回归
        bool regression = false;

        if (current.mean_latency > baseline.mean_latency * (1 + threshold)) {
            std::cerr << "REGRESSION: Mean latency increased by "
                      << ((current.mean_latency / baseline.mean_latency - 1) * 100)
                      << "%\n";
            regression = true;
        }

        if (current.p99_latency > baseline.p99_latency * (1 + threshold)) {
            std::cerr << "REGRESSION: P99 latency increased by "
                      << ((current.p99_latency / baseline.p99_latency - 1) * 100)
                      << "%\n";
            regression = true;
        }

        if (current.throughput < baseline.throughput * (1 - threshold)) {
            std::cerr << "REGRESSION: Throughput decreased by "
                      << ((1 - current.throughput / baseline.throughput) * 100)
                      << "%\n";
            regression = true;
        }

        if (!regression) {
            std::cout << "✓ No performance regression detected\n";
            // 更新基准
            save_baseline(test_name, current);
        }

        return !regression;
    }

private:
    static Baseline run_performance_test(const std::string& test_name);
    static void save_baseline(const std::string& test_name, const Baseline& b);
};

// 在CI中使用
int main() {
    bool passed = true;

    passed &= PerformanceRegressionTest::check_regression("api_latency");
    passed &= PerformanceRegressionTest::check_regression("database_query");
    passed &= PerformanceRegressionTest::check_regression("file_processing");

    return passed ? 0 : 1;
}
```

## 总结

性能分析关键要点：

| 工具 | 用途 | 开销 | 适用场景 |
|------|------|------|---------|
| perf stat | 整体性能统计 | 极低 | 生产环境 |
| perf record | CPU profiling | 低 | 开发/测试 |
| Flamegraph | 可视化热点 | 低 | 所有场景 |
| Valgrind | 内存/Cache分析 | 高（50-100x） | 开发环境 |
| Google Benchmark | 微基准测试 | N/A | 开发环境 |
| BPF/eBPF | 动态追踪 | 极低 | 生产环境 |

**性能分析黄金法则：**
1. **先测量，后优化**：避免盲目优化
2. **持续监控**：及早发现性能回归
3. **真实负载**：使用生产数据测试
4. **系统思维**：考虑整个系统，非单个函数
5. **迭代优化**：小步快跑，持续改进

记住：**测不准，就优化不好！** 📊

掌握性能分析工具，才能精确定位瓶颈，实现极致性能！
